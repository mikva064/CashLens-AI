# Контракт между анализатором и сервисом

Анализатор (человек 1) реализует одну функцию:

```python
def analyze_video(path: str, deadline_sec: float) -> dict
```

- `path` — путь к исходному `.mov` на диске.
- `deadline_sec` — сколько секунд осталось до лимита. Если время на исходе,
  анализатор возвращает то, что успел найти, а не продолжает работу.
- Функция вызывается из одного воркера последовательно; модель можно загрузить
  один раз при импорте модуля или в `load()`.

## Что возвращает

```json
{
  "events": [
    {
      "type": "example_violation",
      "start_sec": 55.0,
      "end_sec": 59.5,
      "key_sec": 57.0,
      "confidence": 0.78,
      "description": "Что именно видно на видео"
    }
  ]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `type` | да | id типа из `rules/rules.json` |
| `start_sec`, `end_sec` | да | границы события в секундах исходного видео |
| `key_sec` | нет | лучший момент для кадра; по умолчанию середина события |
| `confidence` | нет | 0..1 |
| `description` | да | короткое описание наблюдаемого действия |

Чего анализатор НЕ возвращает — это добавляет сервис:

- вердикт (`possible_violation`, если есть хотя бы одно событие);
- кадры-доказательства (сервис вырезает их по `start_sec` / `key_sec` / `end_sec`);
- текст нормы и ссылку (берутся из `rules/rules.json` по `type`).

Так текст нормативного источника никогда не генерируется моделью.

## Ошибки

Любое исключение из `analyze_video` превращается в задачу со статусом `failed`
и текстом ошибки — сервис не падает.
