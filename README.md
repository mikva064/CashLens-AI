# CashLens AI

Локальный анализ видео кассовых операций: события, исходные таймкоды, кадры-доказательства и заранее проверенные нормативные источники.

Репозиторий состоит из двух частей: AI-модуль `src/cashlens_ai/` (анализ видео) и сервис `app/` + `web/` (веб-интерфейс, HTTP API для жюри, очередь, ключ). Контракт между ними — [docs/integration.md](docs/integration.md).

Сервис использует локальную Qwen3-VL-2B-Instruct на NVIDIA GPU в 4-битном формате. Включены три узких правила видеоскрининга по пунктам 20 и 22 постановления НБРК №231. Их область применения, исключения и источники описаны в [реестре норм РК](docs/rk_rules.md). Точность распознавания ещё требует измерения на размеченных примерах; результат предназначен для проверки человеком.

## Сервис: веб-интерфейс и API

### Запуск

Windows: двойной клик по `run.bat` (при первом запуске создаст `.venv` на Python 3.12),
затем открыть http://localhost:8000. Документация API — http://localhost:8000/docs.

Дождитесь состояния «Локальная модель готова к анализу». После загрузки ID задачи сохраняется в адресе `/?job=...`: эту ссылку можно открыть повторно, чтобы продолжить ожидание или увидеть готовый результат. При ошибке автоматической повторной загрузки нет. После обновления кода обновите страницу через `Ctrl+F5`.

Режим анализатора задаётся `CASHLENS_ANALYZER`:

- `mock` (только при явном выборе) — демо-заглушка без GPU; интерфейс и ответ API помечают
  результат как демо (`"analyzer": "mock"`).
- `model` (по умолчанию) — локальная Qwen-модель. Нужны веса в `local/models/qwen3-vl-2b`
  (`CASHLENS_MODEL_DIR`) и непустой проверенный `config/rules.json`. Если чего-то
  нет, `/health` возвращает `degraded` с причиной, а задачи получают `failed` —
  ложный `no_violation` не выдаётся.

Остальные настройки — в [.env.example](.env.example). Тесты: `.venv/Scripts/python -m pytest -q tests`.

По умолчанию включён сбалансированный профиль (`CASHLENS_PERFORMANCE_PROFILE=balanced`): кадры до 384 px при поиске и до 640 px при уточнении, до 8 кадров на уточняющий проход, лимит 131072 пикселя на изображение для модели. Частота поиска остаётся 1 кадр/с, окна — 24 с с перекрытием 4 с. Уменьшенные кадры и более короткая выборка могут пропускать мелкие объекты и короткие действия; точность нужно проверять на разметке.

`CASHLENS_GPU_DUTY_CYCLE` добавляет паузы между вычислениями. Это целевая доля работы, а не жёсткий предел показателя GPU: короткие пики 100% возможны. `CASHLENS_GPU_MEMORY_FRACTION` ограничивает бюджет аллокатора PyTorch после загрузки весов; память CUDA, драйвера и других программ в этот бюджет не входит. В примере `.env` используются 0.65 и 0.70; текущий локальный `.env` при обновлении не заменяйте. После окон и задач очищается неиспользуемая память, а веса остаются загруженными для следующего видео. Ограничение нагрузки может увеличить общее время, поэтому ускорение нужно оценивать вместе с настройками размера кадров.

Для более детальных кадров установите в `.env` `CASHLENS_PERFORMANCE_PROFILE=quality` и перезапустите сервис: 448/896 px, до 12 кадров на уточнение, 262144 пикселя на изображение. GPU-паузы и бюджет памяти сохраняются; значения `CASHLENS_MAX_EDGE`, `CASHLENS_REFINE_MAX_EDGE`, `CASHLENS_MAX_PIXELS`, `CASHLENS_MAX_REFINE_FRAMES`, `CASHLENS_SAMPLE_FPS` и параметров окон переопределяют профиль. Текущие эффективные настройки доступны в `/health` → `performance` и в интерфейсе. Диапазон обеих GPU-настроек — 0.1–1.0; увеличение до 1.0 убирает соответствующее ограничение доли.

При обновлении существующего окружения установите зависимости заново: `.venv/Scripts/python -m pip install -e ".[data,service,model]"`. Проверка работающего сервиса на синтетическом видео: `.venv/Scripts/python scripts/check_local_service.py`. Она проверяет запуск и контракт, а не точность на банковских видео.

### API (ТЗ, раздел 10)

Запросы `/api/v1/*` требуют заголовок `X-API-Key` (`CASHLENS_API_KEY`).

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/v1/analyze` | `multipart/form-data`, поле `file` (.mov) → `{"job_id", "status": "processing"}` |
| `GET` | `/api/v1/jobs/{job_id}` | `processing` / `done` / `failed`; при `done` — результат |
| `GET` | `/health` | готовность анализатора |
| `POST` | `/web/jobs/{job_id}/feedback` | оценка события проверяющим: `event_index`, `decision: confirmed/rejected` |
| `GET` | `/web/stats` | счётчики `confirmed/rejected` по `rule_id` |

```bash
curl -X POST -H "X-API-Key: <ключ>" -F "file=@video.mov" http://localhost:8000/api/v1/analyze
curl -H "X-API-Key: <ключ>" http://localhost:8000/api/v1/jobs/<job_id>
```

Результат `done` собирает `cashlens_ai.integration.to_api_payload` — ровно схема
жюри (`verdict`, `violations[].type / timecode_sec / description / evidence_frames[]`
с JPEG в base64). Дополнительно: `rule_id`, `source` у события, `analyzer`,
`processing_time_sec`, `timings`. Задача в очереди отдаётся как `processing` с
`stage: "queued"`.

Число незавершённых задач ограничено `CASHLENS_MAX_OUTSTANDING_JOBS` (по умолчанию 1, включая выполняемую задачу). При переполнении POST возвращает ID сохранённой задачи со статусом `failed` и `failure_code: "queue_full"`; GET по этому ID также сразу возвращает окончательный отказ без вердикта. Время загрузки, ожидание и анализ входят в общий срок. Просроченная очередь получает `failed`, а не отрицательный результат анализа. Пока модель загружается, новые файлы получают HTTP 503 с просьбой дождаться готовности.

Проверка пяти одновременных загрузок на синтетических роликах:

```powershell
.venv/Scripts/python.exe scripts/load_test.py --url http://127.0.0.1:8000 --output local/load-test.json
```

Скрипт создаёт пять коротких тестовых видео, отправляет их одновременно и проверяет итог каждого в пределах 300 секунд. Для успешной проверки требуется хотя бы один `done`; предсказуемые `failed/queue_full` допустимы, остальные ошибки и превышение срока приводят к ненулевому коду выхода. Это тест ограниченной очереди и доступности сервиса, а не доказательство обработки пяти видео моделью одновременно.

### Как устроено

```text
POST → проверка файла → data/jobs/<id>/video.mov → SQLite: queued
     → родитель-наблюдатель → один дочерний spawn-процесс с заранее загруженной моделью
     → analyzer.analyze(video, data/jobs/<id>/ai, остаток времени)
     → AnalysisResult (кадры-доказательства пишет AI-модуль) → SQLite: done
     → API: to_api_payload (base64) | веб: ссылки на кадры + mp4-превью
```

- `app/` — FastAPI, очередь на SQLite, воркер, ffmpeg (превью для браузера).
- `analyzer/` — подключение AI-модуля: `qwen.py` (модель) и `mock.py` (демо).
- `web/` — одностраничный интерфейс.

Бюджет принятой задачи `CASHLENS_JOB_TIMEOUT` (270 с по умолчанию) считается с начала HTTP-запроса: время загрузки и очереди вычитается из времени обработки. Родитель следит за дочерним процессом независимо от генерации: при превышении помечает задачу `failed`, завершает дерево процесса модели и запускает новый обработчик. На Windows используется Job Object, на Linux — отдельная группа процессов. Повреждённый либо запоздавший результат не становится `done`. Сам приём медленного multipart-запроса этим watchdog не прерывается; если загрузка уже исчерпала бюджет, после её получения сервис сохраняет `failed/upload_deadline`.

В исправном дочернем процессе веса загружаются один раз и используются последовательно для следующих видео. Загрузка и повторная загрузка имеют отдельный предел `CASHLENS_MODEL_LOAD_TIMEOUT` (180 с по умолчанию). Во время перезапуска `/health` показывает `loading`; если подготовка модели не завершилась, сервис остаётся `degraded`, не выдавая ложных вердиктов. Кооперативные проверки внутреннего бюджета остаются дополнительным способом завершиться раньше жёсткого срока.

### Отчёт, оценка качества, источники

- Кнопка «Распечатать отчёт» на странице результата — A4 / PDF с кадрами, нормами и
  строкой для подписи проверяющего. В шапке указаны SHA-256 исходного видео и JSON результата. Отметки «Подтверждаю / Ложное срабатывание» сохраняются отдельно в базе.
- `scripts/benchmark.py` прогоняет отложенные видео через API, как жюри, и пишет
  `local/bench/benchmark.md`: точность вердикта, пропуски, ложные срабатывания, время.
- [docs/sources.md](docs/sources.md) — нормы с цитатами и трактовкой для каждого типа.
- [docs/filming-plan.md](docs/filming-plan.md) — план своих съёмок под другим ракурсом.

Для найденного события сервис дополнительно создаёт мини-клип: до 3 секунд до таймкода и до 3 секунд после него, с обрезкой по границам записи. Поле `violations[].clip_url` добавляется только в веб-ответ и ведёт на локальный файл. Публичная схема API и `AnalysisResult` не расширяются этим полем. В печатном отчёте остаются кадры, а мини-клип используется при просмотре в браузере.

SHA-256 входа считается по байтам во время загрузки файла. Итоговый `/media/{job_id}/result.json` сохраняется как отдельный неизменяемый артефакт; `result_sha256` — SHA-256 точных байтов этого файла, а не пересобранного JSON. Сам артефакт содержит `input_sha256`, но не собственный `result_sha256` и не изменяемые оценки проверяющих. Веб-ответ возвращает оба хеша и `result_json_url`; кнопка скачивания ведёт прямо на сохранённый файл. Изменение оценки не меняет этот JSON и его хеш. Для старых задач без артефакта доступен явно подписанный экспорт текущего ответа без подтверждённого SHA-256. Хеши позволяют сравнить байты и не подтверждают правильность распознанного события.

`GET /web/stats` возвращает `{"by_rule":[{"rule_id":"...","confirmed":0,"rejected":0}]}`. Блок «Отметки проверяющих» показывает эти количества, сопоставляет названия с текущим реестром и обновляется после сохранения оценки. Это статистика оценённых срабатываний; по ней нельзя вычислить точность модели или число пропущенных нарушений без отдельной полной разметки.

## Установка AI-модуля

Нужен Python 3.12. Подготовка данных работает без GPU; модель требует NVIDIA CUDA. Начальная модель — Qwen3-VL-2B-Instruct в NF4. Совместимость конкретной среды проверяет синтетический smoke test.

```powershell
# Только данные, просмотрщик и тесты
./scripts/setup_windows.ps1 -PythonExe python
# Полная среда с CUDA PyTorch
./scripts/setup_windows.ps1 -PythonExe python -WithModel
.venv/Scripts/python.exe -m cashlens_ai.cli doctor
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Библиотеки и веса скачиваются при подготовке. Анализ использует локальные файлы и не обращается к облачным AI. Команды далее запускаются из корня репозитория.

## Данные и локальная разметка

Замените примеры путей своими. Оригинальные ролики и таблица остаются на диске:

```powershell
.venv/Scripts/python.exe -m cashlens_ai.cli audit --labels 'C:/dataset/open_labels.xlsx' --videos 'C:/dataset/videos' --output local/audit
.venv/Scripts/python.exe -m cashlens_ai.cli review --manifest local/audit/manifest.json --output local/review.html
```

Откройте `local/review.html` непосредственно в браузере. Он открывает оригиналы через file URL, не использует внешние ресурсы и не загружает видео на сервер.

Аудит создаёт `manifest.json` с исходными аннотациями и SHA256, `split.json` с разделением по содержимому и `review.csv` с ручными полями. По умолчанию в holdout пять уникальных видео каждого класса. Ручные поля CSV сохраняются при повторном аудите.

Просмотрщик показывает development, позволяет добавить несколько событий, экспортировать JSON и загрузить его обратно для продолжения работы. Импорт проверяет интервалы, временные точки и соответствие видео; ошибочный файл не заменяет текущую разметку. JSON и ручной CSV пока отдельные инструменты: автоматического слияния между ними нет. Holdout оставьте для итоговой проверки. Точка исходной разметки не превращается в интервал автоматически. Разные точки у одинакового ролика сохраняются для ручной проверки.

## Проверенные правила

`config/rules.json` содержит три проверенных нормативных сопоставления: уход из рабочего места при незавершённом приёме, ранее принятые деньги на столе при следующем приёме и пересчёт принимаемой партии без клиента при достаточном контексте. См. [источники и исключения](docs/rk_rules.md) и [формат расширения правил](docs/rules.md). Проверяются только активные условия, а не все возможные нарушения. Нельзя определять невидимые операции в АБИС, намерения или личность людей. Пустой либо непроверенный реестр блокирует классификацию.

## Модель и анализ

```powershell
# Эта команда намеренно использует сеть только для подготовки весов
.venv/Scripts/python.exe -m cashlens_ai.cli download-model --output local/models/qwen3-vl-2b
# Проверка на синтетических изображениях, без банковских видео
.venv/Scripts/python.exe scripts/smoke_model.py --model-dir local/models/qwen3-vl-2b
# Требует заполненного проверенного реестра
.venv/Scripts/python.exe -m cashlens_ai.cli analyze 'C:/dataset/videos/video_001.mov' --model-dir local/models/qwen3-vl-2b --rules config/rules.json --output local/runs/job-001
```

Каждому заданию нужен новый каталог. Там сохраняются `result.json` и JPEG-доказательства. При ошибке или тайм-ауте завершённый результат не выдаётся. Кадры и описания не передаются внешним AI.

Начальные настройки: 1 кадр/с, окна по 24 секунды с перекрытием 4 секунды; уточнение найденных участков с большей частотой и разрешением. Это параметры для измерения, не обещание качества. Короткие действия могут пропускаться, мелкие/перекрытые детали — теряться. Матрица поворота из метаданных контейнера применяется перед уменьшением изображения, анализом и сохранением доказательств; исходные временные отметки сохраняются. Близкие события одного типа могут объединяться; порог задаёт `AnalyzerConfig.merge_sec`.

Генерация ограничена JSON-схемой через `lm-format-enforcer`: только активные ID правил и индексы переданных кадров. Грубый проход возвращает до трёх кандидатов с короткой служебной меткой; уточнение — до одного события на правило и исходное окно с описанием до 96 символов. Служебные метки не попадают в итоговый результат. Для каждого правила в одном исходном окне выполняется не более одного уточнения.

Внутренний ответ модели содержит короткие индексы правил и кадров. Строгий адаптер восстанавливает ID и исходные таймкоды из переданных данных; модель не тратит генерацию на длинные идентификаторы и десятичные координаты.

На уточнении кандидат передаётся как гипотеза с разрешённой временной окрестностью и условием только выбранного правила. Для положительного ответа модель выбирает три предоставленных исходных кадра: до действия, решающий момент и после действия. Среди них должен быть кадр с необходимым контекстом приёма наличных или продолжающегося обслуживания. При недостающем контексте ожидается пустой ответ; заранее заполненного примера с первым классом в запросе нет.

Программа проверяет допустимость индексов, строгий порядок трёх исходных таймкодов, совпадение времени события со средним кадром, наличие выбранного кадра контекста и близость действия к кандидату. В результат сохраняются именно эти три кадра. Противоречивая или неполная структура вызывает ошибку проверки, не вердикт «нарушений нет». Частота выборки и число проходов ради этой проверки не увеличены.

Роли «до / действие / после» и кассовый контекст определяет та же локальная модель. Структурные проверки связывают ответ с предоставленными кадрами, но не являются независимым подтверждением смысла действий. Синтетические тесты проверяют контракт, а не точность обнаружения. Редкая выборка может не захватить короткую передачу денег, завершение операции или клиентскую зону; одно уточнение на правило в окне может пропускать отдельные повторные действия. Перед заявлениями о качестве нужны размеченные положительные и сложные отрицательные примеры, оценка отдельно по правилам и таймкодам. Смещение к первому классу проверяется перестановкой справочника на одинаковых изображениях, а не самим удалением примера из запроса.

Прямой CLI-анализ запускает пайплайн в текущем процессе. Для жёсткого ограничения времени используйте HTTP-сервис с родительским наблюдателем.

## Docker с CUDA

Конфигурация находится в `Dockerfile`, `docker-compose.yml` и `.dockerignore`. Образ основан на [PyTorch 2.8.0 / CUDA 12.6](https://hub.docker.com/layers/pytorch/pytorch/2.8.0-cuda12.6-cudnn9-runtime/images/sha256-dab81780fd94483b67b4b5679cc0024939b08e48540d39476d284cb29002ed69), закреплён digest, содержит системный FFmpeg и зависимости `.[service,model]`. Пара версий `torch==2.8.0` и `torchvision==0.23.0` соответствует [официальной таблице PyTorch](https://pytorch.org/get-started/previous-versions/).

На Windows требуются Docker Desktop, Linux-контейнеры с WSL 2 и поддерживающий CUDA драйвер NVIDIA: [условия GPU в Docker Desktop](https://docs.docker.com/desktop/features/gpu/). На Linux требуется настроенный [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). Конфигурация рассчитана на linux/amd64 и [одну NVIDIA GPU через Compose](https://docs.docker.com/compose/how-tos/gpu-support/).

Заранее скачайте полные веса в `local/models/qwen3-vl-2b/` и задайте свой `CASHLENS_API_KEY` в локальном `.env`. Существующий `.env` не заменяйте: Compose читает его, включая ваши `CASHLENS_GPU_DUTY_CYCLE=0.65` и `CASHLENS_GPU_MEMORY_FRACTION=0.70`. Веса не входят в образ и подключаются только для чтения. Если `run.bat` уже использует модель или порт 8000, остановите обычный сервис перед контейнерным.

Первая сборка и запуск — одной командой из корня репозитория:

```powershell
docker compose up --build -d
```

Сборка скачивает базовый образ и пакеты. После подготовки образа и весов повторный запуск выполняется без сборки:

```powershell
docker compose up --no-build -d
```

Сайт доступен на [127.0.0.1:8000](http://127.0.0.1:8000), API — на [странице документации](http://127.0.0.1:8000/docs). Дождитесь `analyzer_ready: true` в `/health`. Можно проверить состояние через `docker compose ps` и `Invoke-RestMethod http://127.0.0.1:8000/health`. Для другого порта задайте `CASHLENS_PORT` в `.env`.

Видео, кадры, мини-клипы, JSON и SQLite хранятся в именованном томе `cashlens-data`; `docker compose down` останавливает сервис и сохраняет том. Внутри работает один процесс Uvicorn и управляемый им дочерний процесс модели. `init: true` передаёт сигналы дочерним процессам; [healthcheck Compose](https://docs.docker.com/reference/compose-file/services/#healthcheck) допускает начальный период загрузки 180 секунд.

Приложение подключено только к [внешне изолированной сети `internal: true`](https://docs.docker.com/reference/compose-file/networks/#internal), а порт публикуется на [loopback-адресе](https://docs.docker.com/engine/network/port-publishing/). Веса загружаются с `local_files_only`, включены HF offline-флаги. Обычный внутренний bridge допускает связь с самим хостом; прокси для выхода через хост не настроены. [.dockerignore](https://docs.docker.com/build/concepts/context/#dockerignore-files) ограничивает контекст сборки исходниками и публичными правилами, исключая `.env`, видео, изображения, результаты и веса.

На текущем компьютере Docker CLI отсутствует. Конфигурация проверена статически, но сборка, GPU-доступ, публикация порта и исходящая сетевая изоляция здесь не проверены запуском. После установки Docker эти проверки нужно завершить на синтетическом видео; до этого контейнерный запуск не считается проверенным в этой среде.

## Оценка

```powershell
.venv/Scripts/python.exe -m cashlens_ai.cli evaluate --manifest local/audit/manifest.json --predictions local/predictions.json --split holdout --output local/evaluation.json
```

Предсказания — JSON-массив `[{"sha256":"...","status":"done","result":{...AnalysisResult...}}]`. Сбой обозначается `status: "failed"`. Пропуски и ошибки не становятся отрицательными предсказаниями. Смещение к слабым точкам разметки — описательная величина, не официальная метрика локализации. Типы без ручной разметки оценивать нельзя.
