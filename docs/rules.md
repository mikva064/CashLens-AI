# Проверяемые правила

В исходной разметке нет типов событий. Их нужно определить при локальном просмотре и проверить связь с открытым нормативным источником РК.

В текущем реестре уже включены три консервативных условия по пунктам 20 и 22 Правил НБРК №231. Описание применимости и проверки источников находится в [rk_rules.md](rk_rules.md). Наличие нормы не подтверждает точность модели или нарушение в конкретном видео.

Формат одного элемента массива:

```json
{
  "id": "your_event_type",
  "title": "Название после локального просмотра",
  "observable_condition": "Точное условие по видимой последовательности действий до события и после него.",
  "source": {
    "document": "Название реально проверенного документа",
    "section": "Проверенный пункт или раздел",
    "url": "https://example.invalid/replace-with-verified-source"
  },
  "verified": false
}
```

Это шаблон, не действующее правило или нормативная ссылка. Замените поля после проверки. `verified: true` ставит человек. Пустые, непроверенные и повторяющиеся правила блокируют запуск. Модель получает идентификатор, название и визуальное условие. Документ, пункт и URL берутся из реестра.

Условие не должно требовать невидимых системных данных или установления личности. Для пропуска обязательного действия необходимо определить видимое завершение операции и достаточный контекст; короткого окна может не хватить.

Начальная точка исследования — [Правила кассовых операций и инкассации, постановление НБРК №231](https://old.adilet.zan.kz/rus/docs/V1900019680). Применимость конкретного пункта к наблюдаемому действию проверяется отдельно.
